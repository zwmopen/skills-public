# 团建五套对标风格生产器｜公开技能 V1.0（2026-11-04）

## 任务定义｜五种成稿，不是五段摘要

当用户上传**同一套作品的原始图片＋文案TXT/MD**并说“按五套同事范例写”“出这些版本”“调用团建五套风格技能”时：
1. 从**当前批次**素材建立一次真实事实表；
2. **输出5篇完整、彼此显著不同的图文文案**，每篇分别遵循[五种结构蓝图](references/five-format-blueprints.md)中的固定写作指纹；
3. 不把范例中的地点、项目、房型、价格、人数、交通、设施、体验或营业信息搬到当前作品；
4. 默认面向**小红书普通账号的非交易性活动内容**；如果用户明确要求抖音或双平台，按本文件“跨平台”部分执行。**不能承诺规避审核，不能用隐藏的营销话术招揽无资质旅游业务**。

五套模式要“**结构高度复刻，事实与措辞重新创作**”。可迁移的是排列顺序、视觉层次、情绪语气、Emoji、节点密度和分类方法；不能直接照抄他人完整句子。用户说“完完整整”指**每套各有开场、参数、项目/亮点、行程、特色模块、末尾话题的完整作品**，不是把对标稿全文贴回给用户。

### 五套固定交付名与风格来源

| 顺序 / 对外版本名 | 结构来源（仅用于说明风格） | 必须能一眼识别的栏目 |
|---|---|---|
| 1｜快节奏行程型 | 南昆山式 | 情绪开场＋参数卡＋Day1/Day2**箭头串行**＋横排玩法池＋场地特点＋周边备选（有依据时） |
| 2｜详细活动拆解型 | 桐庐山野小院式 | 丰富项目首屏＋**具体钟点**＋核心时段下**多行▶细节**＋娱乐/美食/景点分栏（有依据时） |
| 3｜田园农庄体验型 | 广州小院式 | 乡野生活开场＋一日或两日参考时间轴＋特色体验详解＋餐饮与场地特点＋密集项目菜单 |
| 4｜山野季节攻略型 | 四明山式 | 季节/自然钩子＋具体参考钟点和对应一句体验＋季节玩法九宫格**文字排列**＋景观细节 |
| 5｜主题沉浸玩法型 | 阳澄湖式 | 主题元素开场＋简洁选择理由＋参考时间轴＋**3—4组独立主题体验（每组短段）**＋分类活动池 |

上述只是风格映射，**不是五个固定地理地点**。同一套莫干山TXT生成的五篇都只能写当前莫干山真实素材，不得出现南昆山/四明山/阳澄湖的无关事实。即使原始素材只有4项活动，也要在不同模式中重排这4项，而非编造20项。

## 读取当前素材的最低摩擦工作流

1. **锁定当前作品**：当前用户消息所指的这一批TXT/MD、原始图片、明确文字说明。当前窗口首次视觉母版A类仅学习排版，不作为事实源；其他批次的B/C图片也不借事实。
2. **先TXT后图**：优先完整读取与当前批次有关的原始TXT/MD，包括地点、时长、景点、玩法、餐食、设施、人数、开放条件、可选项及原有排程；文案TXT若是竞品或AI草稿，应视为**待审核原料，不是所有承诺都被确认**。
3. **按需核对图片**：当TXT缺地点/玩法/住宿/餐食或用户明确要求图文一致时，直接看相关原图的可见内容；不默认逐张OCR或读取水印文字。图片表现的景物可以支持画面描写，但无法单凭照片确定包场、接送、价目、保险、实际服务提供。
4. **一张内部事实表**：分类 `已确认`、`可选`、`未核实`、`范例风格`。一旦发现TXT与图片冲突，优先使用用户当轮明确确认的信息，否则删去不确定细节；不为凑丰富度搜索无关项目。
5. **一次构思五种不同结构**：所有版本共享事实表，但必须在**首屏钩子、栏目顺序、时间轴格式、项目描述和主题侧重**上显著不同。禁止只是改标题、换Emoji或重复长段。
6. **按一日/两日动态编排**：TXT明确1日只写1日；两天才写Day1/Day2。参考钟点是策划排列，不是假称固定车程、真实抵达/开业时刻；多地空间距离未知时将项目做互斥的下午路线或替换项，避免不可执行的全天大串联。
7. **轻量发布前检查→交付**：项目可见度、排版、真实性、平台风险、标题话题、完整度和文件逐字一致性；无需展示大量内部研究过程。

### 图片与TXT的事实优先级

**当前用户明确确认的事实** > **当前批真实原始TXT/MD** > **当前批原图可确认的场景/文字** > **必要时定点核实的公开资料** > **仅用于风格的参考模板**。如果用户称当前TXT是“别人家的案例”，其中的项目不能默认当作自己作品真实包含项；先明确它是“可参考的项目类型”，不要生成已经预订/已包含的虚假承诺。不得让其他批次污染事实。

## 五篇的共同质量标准

- **各自完整**：标题＋前3行留人＋地点/时长（有依据）＋**密集真实活动清单**＋参考节奏＋该模式专属栏目＋8–10个小红书话题。目标每篇约**800–950发布字符**（含标题、Emoji、标点、U+2800和话题），宁可简短也不虚构凑字；单薄素材允许低于目标并说明原因。
- **标题**：小红书标题≤20字符；以目的地＋真实玩法或季节画面为主。禁“全要素”“服务矩阵”“方案定位”“项目标的”“咨询方式”及`标题：`前缀。
- **排版**：大模块间用**一行 U+2800 字符 `⠀`**；连续时间轴/项目清单内部紧凑换行，不要一行活动后加空行；避免原始范例的`&#x20;`、反斜杠换行、`#话题[话题]#`等复制噪声。
- **活动密度**：第一屏尽量出现3–5个真实活动名；每篇展示能被本批素材支持的主要项目，`✅项目｜一句可感知的活动内容`或`A｜B｜C`；同一动作（如“备菜/掌勺/吃饭”）不是三个独立场地项目。
- **先活动，后少量提醒**：不重复“别排满、按需、出发前确认”等文字充数。必要的交通、开放、天气、用火和水上安全提示集中末尾1–2句。
- **实质合规**：无证据不写固定车程、具体接送/包车、报价、房型、保险、人数承接、免费、项目全包含、假亲历或“每个人都说好”；无真实依据不写商业承接。提供普通游玩信息不是替代运营资质。未经确认的项目、菜单、住宿条件不写成既定套餐。
- **CTA**：非经营性内容只允许真正的内容交流，如“收藏作参考、补充玩法、分享踩坑提醒”。不要以“留人数/预算、评论团建、私信领取、加微”等规避监管或引流招徕为目的。如果业务实质是商业组团/旅游招徕，必须按实际业务检查适用资质、平台准入与广告披露，而非改词掩盖。

## 双平台行为（用户要小红书＋抖音时）

- 默认指令“生成五套”＝5篇**小红书**独立稿。
- “抖音五套”＝按相同五套内容组织技巧，**重新创作5篇抖音日常攻略**（不能把小红书的商业/团建组织框架原样复制）；话题4–5个，标题不需要“团建”业务标签，不展示人数、接送、含餐含住等旅游经营承诺；不装作亲历。时间线只有在真实个人分享或中性的开放式活动建议下使用，避免完整套餐式“集合—接送—住宿—餐饮—返程”招徕语境。
- “双平台五套”＝5篇小红书＋5篇各自对应风格的抖音重构，共10篇；单篇平台与风格分开标记。素材不足则诚实缩短，不虚构玩法。**删掉联系方式不能使实质商业招徕合法**。
- 用户明确点名仅三种模式或仅一版时只生成被点名的版本，不擅自扩大数量。

## 交付协议（支持新账号与批量生产）

1. 先输出**5个独立纯发布文案的复制代码块**（标题、正文、#标签），每份代码块外标注版本名，内部没有机器标识；当双平台时按平台分组输出。
2. 再输出一个完整 `<<<COPY_FORMAT:MULTI>>>` 合并代码块：每版使用 `<<<VERSION_START:小红书1｜快节奏行程型>>>` … `<<<VERSION_END>>>`，依次至5；抖音对应名称改为`抖音1｜...`。机器分隔符不属于发布文案，不计字符。
3. 在支持文件生成的环境中，**实际创建UTF-8的 `文案.txt`**，内容与合并代码块逐字一致，保留Emoji、U+2800、换行；验证文件存在后提供真实链接。不可创建时不伪造链接。
4. 对现有旧主技能 `skills/teambuilding-copywriter/SKILL.md` 和原生产线的旧`VERSION_START`名称**不做破坏性更改**；本技能使用自己的5个风格标记。若本地解析器只认旧版5名，需为新预设建立显式映射，不能把“主题沉浸玩法型”误标为抖音版本。
5. 最终文字只简要说明产出、有效性约束。用户不要求时不长篇展示读取/质检过程。
