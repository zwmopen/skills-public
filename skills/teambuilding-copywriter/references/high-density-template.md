# 小红书2｜高密度种草版模板 V1

> 定位：用户于 2026-10-22 明确指定的新长期输出模板。它是一个 **output_mode / 表现体模板**，不是新的事实来源，也不是新的底层 style_id。
>
> 核心感觉：**标题能搜、第一屏有情绪、信息卡一眼扫完、亮点写得诱人、路线/时刻清楚、玩法池够丰富、Emoji 与标记密度高、结尾 SEO 话题完整。**
>
> 使用时只借版式、语言节奏、标记、信息密度和组织方式；不得把示例里的地点、人数、车程、价格、开放状态、项目数量、客户承诺迁移到其他素材。

## 1. 一句话识别

这是“**高密度种草 + 方案信息 + 路线时间轴 + 玩法池 + SEO 话题**”的复合型小红书模板。

它与另外两个默认版本的区别：

- 小红书1｜自然攻略版：更像成熟运营自然分享，信息够用但不堆；
- **小红书2｜高密度种草版：更热闹、更有画面、更有关键词、更有项目名、更强视觉层级，读起来像“这地方好多东西能玩”。**

## 2. 标题系统

### 标题功能
标题不只概括内容，还同时承担：
1. 地域搜索词；
2. 团建搜索词；
3. 2—4 个最有诱惑力的真实玩法；
4. 季节/氛围钩子。

### 优先母型

```text
{地点团建}｜{强玩法A}+{强玩法B}+{强画面C}🍂
{地点团建}｜{项目A}+{项目B}+{季节结果}
{目的地}团建｜{高辨识度项目组合}
```

优先把 **最有画面的项目组合** 放在标题里，例如：
- 徒步 + 采摘 + 露营
- 骑马 + 越野 + 土灶
- 橘园 + 骑行 + 围炉
- 水杉 + 骑行 + 皮划艇

### 标题禁区
- 不得只写“XX怎么玩 / XX怎么搭 / XX怎么选”；
- 不得只用地点 + 团建 + 秋季这种泛词；
- 不得靠“天花板 / 杀疯了 / 闭眼冲 / 老板夸爆”制造点击；
- 事实不支持的项目、人数、价格、车程不能为了标题诱惑力硬塞。

## 3. 第一屏语言

第一屏要比自然攻略版更“有情绪”，但不能假装亲历。

推荐结构：

```text
{一句季节/打工人情绪钩子}🍂
{一句为什么现在值得去 / 这套组合最有意思的地方}
{一句高密度玩法总览}🌳
✅ {一句可收藏/可抄作业的结果感，但不写强获客CTA}
```

语气关键词：
- 秋高气爽
- 逃离工位
- 山野漫游
- 追风
- 秋日限定
- 一天玩出几种感觉
- 白天撒野，傍晚慢下来
- 动起来 / 慢下来
- 一次把山野、吃饭、夜晚都接上

避免：
- 虚构“刚带完一个团队”
- “全员尖叫 / 0差评 / 老板夸爆”
- “一站式搞定”除非用户明确要保留商业承接表达且事实支持。

## 4. 信息卡排版

保留高识别度竖卡格式：

```text
•
📍 | {地点}
⏰ | {时长}
🙋‍♀️｜{人数，有依据才写}
🚌 | {交通/接送，有依据才写}
🎯 | {3个核心体验关键词}
•
```

规则：
- 有事实才写字段；缺失字段直接删，不写“未提供”；
- 允许 3—5 行，绝不为了凑齐卡片编数据；
- 项目密度可以高，但必须是真实素材支持。

## 5. “亮点速览”模块

固定保留这种视觉层级，但小标题可按素材变化：

```text
⭐行程亮点速览

🏔️{玩法/场景A}：{1—2句具体画面 + 为什么值得}
🏎️{玩法B}：{体验差异 / 强度 / 爽点}
🌈{玩法C}：{项目组合 / 适合谁 / 怎么取舍}
🌰{玩法D}：{季节性体验 + 必要提醒}
```

写法要求：
- 每项必须有“项目名 + 画面/体验 + 一个判断”；
- 不是机械罗列名词；
- 语言可以比小红书2更鲜活、更有动词；
- 不要每项都补一段免责声明，风险提醒集中到末尾。

## 6. 路线 / 时间轴模块

只有输入明确支持时间、DAY 或先后顺序时才启用。

模板：

```text

𝗗𝗔𝗬❶
10:30｜{节点}
11:30｜{节点}
13:00｜{核心项目}
15:00｜{核心项目}

18:00｜{晚餐/烧烤}
19:00｜{夜间活动}
20:30｜{住宿/结束}

•

𝗗𝗔𝗬❷
09:00｜{节点}
10:00｜自选行程：
✅ {A}
✅ {B}
✅ {C}
12:00｜{节点}
14:00｜{返程/收尾}
```

规则：
- 时刻、先后、DAY 都必须来自真实输入；

- 多个地点是否能串联必须真实可支持；不能把跨区域项目硬拼成一条“看起来很完整”的路线；
- 自选项优先用 `✅` 做视觉分流。

## 7. 玩法池模块

这是本模板很重要的“丰富感来源”。

模板：

```text
🍁【秋日限定体验】
徒步采摘🍁｜露营烧烤🔥｜围炉煮茶🍵
山野骑行🚴｜植物手作🌿｜趣味运动会🏃
定向寻宝🗺️｜ATV越野🚗｜飞盘嘉年华🥏
```

规则：
- 只放素材里真实支持的玩法；
- 玩法多时可 6—15 项，少时宁可短，不得为了“丰富”虚构；
- 这部分是“玩法池/可选项”，不等于同一天全部执行；
- 季节性、涉水、明火、驾驶、高空等项目仍服从事实和安全门。

## 9. 话题系统

- 1—2 个核心项目词
- 1—2 个场景/季节词

## 2026-10-22｜高密度种草版时间轴授权

用户明确要求：**小红书2｜高密度种草版可以由模型主动规划“参考行程时间轴”**，不必等原素材逐条提供具体时刻。

执行规则：

- 必须把整段标成 `🗓️ 1日行程参考 / 🗓️ 2天1夜行程参考 / 参考时间轴`，表示这是可调整的策划排程，不是景区固定营业时间或供应商承诺；

- 若存在用户明确时刻，则优先使用用户时刻；若没有，则高密度种草版可以主动补出完整参考时间轴；
- 小红书1/2是否主动补时刻仍按各自规则执行；此授权重点用于小红书2高密度种草版，使它真正复刻“信息卡 + 亮点 + 时间轴 + 玩法池”的模板完整度。

## 13. 丰富度默认值（2026-10-22追加）

高密度种草版的默认目标不是“克制”，而是**信息丰富但层级清楚**。素材足够时优先做到：

- 第一屏：3—5 行，至少包含季节/情绪钩子 + 目的地/场景 + 项目丰富度 + 一句结果感；
- 参数卡：4—5 行；
- 亮点速览：4—6 个核心亮点，每个亮点 1—2 句，不只列名词；
- 参考时间轴：一日稿通常 6—9 个节点；2天1夜每日至少 4—7 个节点。无原始时刻时可自主规划“参考时间”；
- 玩法池：素材充足时 9—15 项，使用 `｜` 横向排布；路线里只执行部分项目，玩法池负责展示丰富度；
- 组合建议：2—3 组，用 `✅` 或短标签快速分流；
- 话题：通常 8—10 个，覆盖地域、目的地、核心玩法、季节/时长、团建方案搜索词；
- Emoji：每个核心模块有专属图标，避免整篇只重复 🍂🌿🔥；
- 大段之间可继续使用 `•`，形成和原始范例一致的视觉呼吸。

### 不要把“丰富”误写成“全部塞进路线”
高密度版分成两层：
1. **主路线**：挑 3—5 个项目形成合理的一天/两天节奏；
2. **玩法池**：把其余真实可选玩法继续展示出来，体现“项目丰富”。

因此不再因为“不要排太满”就把大量真实玩法从文案里删掉；应该是**路线做减法，展示做加法**。

### 小红书可用的业务运营词
在用户当前业务口径下，小红书可以自然使用：
`项目丰富 / 可灵活定制 / 大巴接送可安排 / 10人起 / 一站式沟通或安排 / HR抄作业 / 团建方案 / 一日团建 / 2天1夜团建`。

这些词不需要像抖音一样消杀。具体价格、固定车程、固定包含项、场地官方开放时间仍不得凭空编造。

### 风险提醒位置
高密度版不要每个项目后都写“以实际为准”。天气、采摘、涉水、明火等提醒统一压到倒数第二段，用 1—3 句收口，避免破坏种草感。


## 2026-10-22｜高密度版空行收紧

用户明确反馈：高密度种草版中，单独一行的 `•` 再配合 U+2800 会让视觉空隙过大。后续生成规则调整为：

- **删除独立圆点分隔行 `•`**；
- 段落之间统一只保留一行 U+2800：`⠀`；
