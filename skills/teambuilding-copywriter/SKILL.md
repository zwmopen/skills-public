# 团建文案 Skill｜公开版

## 2026-11-03｜发布态术语防泄漏与反PPT硬质检（最高优先级，先于字数/密度）

**事实来源特殊处理**：用户贴来的旧版AI文案、竞品文案或反面样稿属于“待审文本”，**不等于用户已确认全部服务细节真实**。除非同批原始资料或用户明确确认，不能将旧稿里的车辆座数、酒店配置、保险、雪具包含、接待人数和具体服务承诺重新包装成确定事实。

**用户实测反例**：一篇滑雪年会稿被写成“江浙沪2天1夜年会方案全要素清单”，正文又有“一、全要素服务矩阵明细”“【项目标的】”“【方案定位】”“三、咨询方式”，还未经证实地写了具体大巴座数、酒店设施、雪具包含、教练、保额、精修摄影与“留人数+预算获取排期”。这表明旧版“内部称全要素、标题别写全要素”的提醒**不足以拦截**，必须逐版对最终标题＋正文做发布态硬检查。

### A. 内部风格标签与外部发布文本严格隔离

- “高密度全要素方案版 / full-element-plan / 服务矩阵 / 项目标的 / 方案定位 / 综合服务 / 全要素”属于**内部写作和业务分析元数据**，不是读者搜索词或种草卖点。它们可以作为代码块外的版本名和MULTI的分隔符，但**不得出现在任何一版直接发布的标题或正文**，除非用户明确要求写一篇解释这些概念的文章。
- **机械硬检查**：抽取五版每一篇独立的纯发布正文（去掉代码围栏、版本名、`VERSION_START/END` 等分隔标记），搜索`全要素`、`服务矩阵`、`项目标的`、`方案定位`、`综合服务`、`咨询方式`。命中即判本版 **FAIL_INTERNAL_TERM_LEAK**，必须**重写相关标题或整段**再验收。不能仅把词删掉而留下PPT腔。内部版本标签允许出现“全要素”，不因此误报。
- 发布稿小标题优先真实内容：`🗓️两天参考安排`、`⛷️滑雪怎么玩`、`🏡住宿怎么选`、`🎯适合哪些团队`、`🍲吃什么`、`🎮可选玩法`。不按投标文件章节写`一、交通保障`、`二、服务矩阵`、`三、咨询方式`。
- **标题约束再提升**：≤20字符之外，必须有实际景点/玩法/氛围/决定性选择价值之一；SEO最多围绕1—2个主词自然组织。不同地域叠加、长串功能词、内部分类词、毫无证据的“保姆全案/一站式”等标题均重写。比如已确定桐庐、滑雪、年会和温泉选项时，可考虑“桐庐年会团建⛷️滑雪＋温泉”，但`温泉`必须有本轮已核实的泡汤事实，不能因旧参考图/范例而添上。

### B. 商业承诺与示例项目防迁移

- 最终稿出现**具体包车座数、高速/过桥费、雪具租赁包含项/滑雪时长、教练服务、民宿全地暖/天然私汤/会议室配置、固定人数承接范围、保险额度、摄影精修、行程固定到达时刻**等细粒度运营事实时，逐项追问是否来自**本批真实用户材料或已确认业务能力**。若缺，删除或明确为未确定的可选方向，不用“全套、含、标配、全程提供”造承诺。
- `30万保险`、`33/53座大巴`、`15–80人` 等看起来像参数的数字没有真实依据时直接判 **FAIL_UNSUPPORTED_CLAIM**；不能用模糊“均已包含”替代。
- 没有已确认资质与平台准入时，绝不凭“无营销”改写方式声称旅游/团队服务推广一定符合平台规则。
- 不默认输出`留下人数+预算`、`领取详细方案`、`私信获取`、`咨询方式`、`加微`等强转化CTA。**这不是所有词在所有场景下的永久违法判定**；只是本项目的默认公开稿不承接这些营销动作。

### C. 输出前强制闭环（每一版都做，不可只在模板里提醒）

1. **看标题**：是否含`全要素`等内部标签、超过20字符、只堆关键词而没有一个真实玩法/画面钩子？
2. **看正文**：是否出现商务招标/PPT腔的段落名、营销承接CTA或不证实的服务矩阵/配置清单？
3. **看证据**：把数字、保额、含项、设施、包栋、温泉、雪场装备、交通和时刻等承诺逐项对本批来源；无依据就删。
4. **看交付**：修正后再检查字数、话题、U+2800、3/4版行程和独立/MULTI/TXT逐字一致性。**有任一FAIL则不得把该稿当可发布完成稿交付**；不够素材就交代事实缺口。
5. 不需要每次大段展示质检过程，但必须实际按此顺序执行。**仅把禁止项写进SKILL.md，不等于已经通过质量检查。**

### 用户偏好的高密度活动排列｜先给玩法，再作简短说明（2026-10-30.1）

> **“看起来活动丰富”是一个明确的视觉信息结构要求，不是“编造更多活动”的授权。** 参考用户提供的余杭露营、阳澄湖、临安、莫干山、青山湖、溧阳、桐庐等真实文案样例的**写作结构**，提炼见 [`references/rich-activity-layout-corpus.md`](references/rich-activity-layout-corpus.md)；另见[`活动密集排版指南`](references/activity-dense-layout-style-guide.md)；样例仅作为风格原料，**不作为新作品的事实来源**。

- 第3版高密度种草：读者应在前半篇看到 **4–6项有名字、有体验的亮点**，例如 `✅采摘垂钓｜湖边慢玩，适合轻松组`。真实玩法较多时，再提供 **2–4组横向紧凑排列的活动池**，如 `🔥动手：分工备菜｜土灶野炊｜露营烧烤`。不以“别排满/需确认/建议择一”等段落替代玩法展示。
- 第4版高密度排程：优先交付**清楚可扫的带时刻主行程**，重要节点下把同场地且有依据的活动用`A｜B｜C`并列展示，再补 **分类玩法、餐饮/住宿与周边替换项**（有素材才写）。内部叫“高密度全要素方案版”，**对外标题禁止出现“全要素”等内部分类名称**。
- **丰富感合格标准**：实际有6项就尽可能展示6项不同的真实活动；不把`草坪聊天/草坪休息/草坪走走`冒充三个项目，不写`20+`而实际上只有6项。活动类型、场地和是否能串联必须有来源，未知时标成可选/互斥，不得写成单场地全含。

- **一日/两日动态**：单日只写一日时间轴，两日才写D1/D2；节奏要符合用户已知的地理路线，不为了排列漂亮强行串联多场地。

### 具体参考时间轴｜高密度版本硬要求

**区分“原始事实”和“策划时间”**：真实项目、已知目的地、已明确天数来自当轮素材；若未给出具体钟点，但已确定一日/两日时长与确实可安排的项目，明确授权模型自行拟定**有四位时刻的参考排程**，并在读者可见位置写“🗓️ 两天参考时间轴/参考安排（时间可调整）”。可用 `09:00｜`、`11:30｜`、`14:00｜`、`18:30｜`；不得伪装景区开放、班次、入住时间、真实车程或供应商固定承诺。

- **小红书3**：素材足够时必须有醒目的“4–6项逐行亮点＋2–4组紧凑横排玩法池＋简明具体时刻参考行程”；不能只写“上午徒步→下午泡汤”。
- **小红书4**：以逐时主轴、单行活动矩阵、真实项目可选池呈现丰富度；当两天时长且真实项目足以组成可行排程时，**D1、D2均采用具体时刻**，优先覆盖出发/午餐/核心项目/晚间与次日体验/收尾。时间轴是正文**主轴**，再按事实容纳玩法清单、餐饮、住宿、备选点位、2–3种组合，不能为了填满栏目编事实。必要时精简重复说明，**不能先删具体时间轴**。
- **小红书2**：有真实时刻优先保留；若仅有活动与时长，可以做明确标注的参考排程，但不强制每次逐时。
- **小红书1**：仍以自然运营口吻为主，不强制时刻。
- **抖音版**：独立生活分享，不直接照搬小红书的B端具体排程或商业表述。

客观时刻（如真实车次、营业时间、固定交通耗时）**只能有当轮可靠证据才能写**；策划时间可以拟定，但不允许假称已实地验证。不同地理点位之间的接驳时间与动线未知时，把它们写成互斥备选，不得生造精确抵达时刻。没有明确天数或可信项目时，不强行补表，说明事实不足。

高密度不等于灌水：禁止用五版重复“提前确认/不要排满/因人而异”凑到800字符；每一小节增加真实玩法信息、具体体验或决策价值。避免“参考内容有”“照片里写了”“不要把所有图当套餐”等AI生产过程旁白。

### 默认交付格式：先独立，后合并

**A｜独立复制版：** 先输出五个独立代码块。每个代码块只放可直接发布的完整文案（标题、正文、话题）。版本名称可以放在代码块外。

**独立复制版禁止出现任何机器标记**，包括 `<<<COPY_FORMAT:MULTI>>>`、`<<<VERSION_START:...>>>`、`<<<VERSION_END>>>`，也不得夹带任务编号、验收旁白或非发布标签。

**B｜完整合并版：** 再输出一个 `text` 代码块，格式如下：

```text
<<<COPY_FORMAT:MULTI>>>
<<<VERSION_START:小红书1｜自然攻略版>>>
[与独立复制版逐字一致的完整文案]
<<<VERSION_END>>>
<<<VERSION_START:小红书2｜大纲方案版>>>
[与独立复制版逐字一致的完整文案]
<<<VERSION_END>>>
<<<VERSION_START:小红书3｜高密度种草版>>>
[与独立复制版逐字一致的完整文案]
<<<VERSION_END>>>
<<<VERSION_START:小红书4｜高密度全要素方案版>>>
[与独立复制版逐字一致的完整文案]
<<<VERSION_END>>>
<<<VERSION_START:抖音｜攻略版>>>
[与独立复制版逐字一致的完整文案]
<<<VERSION_END>>>
```

合并版只允许在独立文案外增加分隔标记行。每篇文案必须与对应独立版逐字一致；不得重写、压缩、删段、删标签或调整标点。标记行不属于发布文案，也不计入字符数。

### 统一字符计数口径

- 计数从每版标题/首句到最后一个话题标签，包含正文、标题、Emoji、标点、空格、U+2800留白字符和话题标签。
- 不计代码围栏、代码块外版本名称、机器分隔标记。
- 小红书标题≤20字符；小红书每版8–10个相关话题；抖音4–5个话题且最多5个。
- 逐版检查事实、长度、标签、排版、风格差异和独立/合并版逐字一致性；没有实际检查就不得声称通过。

### 链接直入

用户直接发送公开小红书链接/分享链接时，默认尝试读取标题、正文、话题和可访问图片，提取事实后直接生成五版与两种交付格式。若无法完整读取，明确说明并请用户补发分享文本/截图；不得假装已读取，不得用搜索摘要冒充全文。

用户只需说“按团建文案技能写文案”或“按这个链接写五版”即可，不必反复粘贴长提示词。快捷提示词见 `references/quick-start-link-prompt.md`。用户当轮明确指定部分版本或某种格式时，以当轮要求为准。

### 网页交付附加：真正创建 `文案.txt`

默认交付五个独立代码块 + 一个 `<<<COPY_FORMAT:MULTI>>>` 合并代码块后，**实际创建 UTF-8 文件 `文案.txt`**。五份独立稿一次起草并定稿；合并版和TXT须由已定稿正文直接组合生成，不能重新写一遍，以避免重复耗时和文字漂移。文件内容与合并代码块内部的全文逐字符一致（包含 `<<<VERSION_START:版本名>>>` 和统一 `<<<VERSION_END>>>`）；保留Emoji、U+2800及换行，不包含Markdown围栏。必须验证文件真实存在后给出下载链接；文件能力不可用时，保留五版和合并代码块，明确无法提供下载，严禁伪造链接。若某平台无法读取部分附件，优先使用已核验素材降级，绝不能编造事实凑数。

## 一、共同事实原则

在内部一次性建立简短事实账本（不要求展示），只使用当前输入中明确支持的信息，以及用户已明确授权可作为长期业务能力使用的信息。

可以使用：目的地、城市、场地、季节、玩法、天数、人数、交通、住宿、餐饮、已证实的项目与设施，以及已明确的可安排服务能力。

不得编造：价格/人均、固定车程、固定接待容量、营业时间、开放状态、客户案例与评价、项目包含关系、房间设施、承诺、安全结论。不得把“备选玩法”写成同一天必然全部执行，不得把不同场地或住宿写成同一个套餐。

禁止生产过程旁白：不得出现“原文参考、原素材、图片显示、根据资料、这里没有提供、本文整理”等表达。有依据就直接写，无依据就省略。

## 二、小红书1｜自然攻略版

目标：像成熟运营自然分享，具体、顺口、信息够用，不刻意堆模块。

建议结构：不超过 20 字符的画面感标题；场景/痛点/选择结论开头；地点、人数、核心玩法等基础信息（有依据才写）；不同强度或氛围的玩法选择；傍晚收尾方式；HR/组织者搭配参考；一组必要提醒；8–10 个搜索标签。

自然攻略与其他版本必须独立构思，不得只换标题、Emoji 或小节名。

**长度：800–950 发布字符。**

---

## 三、小红书2｜大纲方案版

目标：面向 HR/行政或团队组织者，形成可收藏、可判断、可调整的方案大纲，不写成干瘪的四问四答。

建议结构：具体标题；基础信息；核心项目及各自适合的人群/强度；合理的参考节奏；不同团队的取舍与搭配；必要提醒；8–10 个相关话题。

只有素材或用户授权支持时才写具体时刻；模型规划的时间必须明确标注为“参考”，不得伪装成景区班次、固定营业时间或真实车程。

**长度：800–950 发布字符。**

## 四、小红书3｜高密度种草版

目标：更丰富、更热闹、更好扫读、更强搜索感；参考时间轴为有条件必交付要素，重点回答“有什么值得玩、画面在哪里、如何灵活搭配”。

建议结构：地点＋强玩法组合标题；有情绪但不假装亲历的第一屏；参数卡（只保留有依据的字段）；**连续可扫读的项目菜单（✅活动名｜画面/体验，或分类的项目A｜项目B｜项目C）**；4–6 项具体亮点可与清单合并；合理的参考时间轴；丰富但明确标注为可选的玩法池；集中提醒；8–10 个 SEO 话题。信息丰富优先体现在具体活动，而不是反复解释怎么选。

标题优先呈现真实项目组合。每项亮点都写出“项目/场景＋具体体验＋判断”，不只堆项目名。可以策划参考时间，但不能编造客观营业、交通或开放事实。

**长度：800–950 发布字符。**

## 五、小红书4｜高密度全要素方案版

目标：以D1/D2四位时刻参考排程为主轴，帮助组织者判断如何排程与搭配，素材充分时覆盖完整参考行程、玩法清单、餐饮住宿、备选景点及不同团队组合。

建议结构：情绪与场景开场；明确标为参考的 DAY1/DAY2 或时段排程；**高密度短行分类玩法池**（自然、趣味、活力、餐饮/夜场，仅保留有事实的类别）；有事实才写餐饮、住宿、设施和备选景点；2–3 种基于兴趣/体力/团队氛围的组合建议；必要提醒；8–10 个话题。优先用项目名称、动作、活动差异增强丰富感，不靠反复免责声明凑字数。

可以写一条主路线＋多个备选，也可以比较两套互斥方案；必须明确互斥关系，不能把两条路线拼成不可执行的套餐。素材不支持的栏目直接省略，不得为凑齐模块而编造。

**长度：800–950 发布字符。**

## 六、抖音｜攻略版（无营销）

目标：普通用户周末散心、户外体验或自驾分享口吻。必须独立重构，不复制小红书的团建商业承接表达。自然分享口吻不等于保证平台合规。

严格禁用涉旅营销/承接词，包括：**团建、HR、行政、方案、策划案、大巴接送、报价、人均、预约、下单、私信、加微、加微信**。不得使用“DAY 1 / 行程安排 / 活动流程”等方案腔表头；不虚构“我刚去过”等亲历。

只保留 4–5 个生活、户外、自驾或目的地相关标签，最多 5 个。若素材涉及经营性旅游服务，应另行核实主体资质与平台准入；文案无法替代资质核验，也不能保证过审。

**真实处罚案例专项复核：** 参见 [`references/douyin-violation-cases.md`](references/douyin-violation-cases.md) 的 DY-001。抖音曾对一条无报价/联系方式、但包含「2天1夜＋DAY1/DAY2完整路线＋食宿游玩＋团队出游＋#团建」的溧阳作品作出「旅游业无资质营销」处罚。用户另补充「15人」信息，尚未核实其在作品中的出现位置。今后需将「明确天数＋人数＋团队组织语境＋完整旅游服务行程」的**组合**纳入人工复核，检查视频封面、字幕、口播、标签和账号经营主体资质；不得武断宣称任一词单独触发，也不得以换词规避应有资质。

**长度：800–950 发布字符。**

## 七、标题、排版与验收

- 小红书标题不超过 20 字符，且可直接发布的代码块标题不带「标题：」前缀；优先真实场景、具体玩法组合、季节画面或清晰的选择价值。避免泛化的“XX怎么玩”，不靠“天花板、杀疯了、闭眼冲、老板夸爆”等词制造点击。
- 正文段落之间使用独立一行的 Unicode U+2800 字符 `⠀`；不使用 HTML 空格或 `<br>`。
- 五版要有明确风格差异，不能互相换词冒充独立成稿。
- 验收第3/4版的**项目可见度**：读者是否一眼看到足够多的真实项目名称、合理分类与密集排版；若多数篇幅只是解释、免责声明和空泛建议，则该版不通过。真实项目少时不许凭空增项。
- 发布前逐版检查：**先执行2026-11-03的内部术语/PPT腔/未证实服务与强CTA硬门**，再检查事实依据、生产旁白、标题长度、发布字符数、标签数量、抖音禁词/方案腔、段间留白、两种格式内容一致性。可用Python时运行 `python scripts/qa_publish_text.py 文案.txt`；返回非零意味着有文本错误必须重写。脚本中 `REVIEW_EVIDENCE` 属于需按本轮来源人工核实的预警，不代表机器已经验证事实或平台资质。
- 任一版本未通过，先定点修订不合格项并重新核验；不得为了形式而重跑全部研究，不得声称已经通过未实际执行的检查。
- 用户只需说“调用团建文案技能写文案”，默认就按本节五版＋双格式合同执行；不需要重复粘贴旧的三版提示词。若用户当轮明确指定其他数量或格式，以当轮明确要求为准。
